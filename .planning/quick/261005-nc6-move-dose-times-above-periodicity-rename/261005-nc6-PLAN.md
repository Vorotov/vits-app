<decisions>
Decisions this plan makes, so the executor does not re-litigate them:

**D-1. One new save key, not two.** Only the non-paused branch splits. The
paused label `saveWhilePaused` ("Save, cycle paused" / "Зберегти, цикл на
паузі") is already correct on the edit path — it says Save and states the state.
So the footer becomes a three-way, not a four-way.

**D-2. The save hint does NOT get an edit variant.** `saveHintActive` ("Slots
will appear in the calendar from {start}. Pause removes them without deleting
your settings.") states what this save does, and that is true whether the
regimen is new or being changed; its pause clause is more relevant on the edit
path, not less. A create/edit x active/paused matrix would be four strings in
seven languages — 28 values — for a sentence whose content does not change.
Record this decision in the `_EditorFooter` doc comment, per the repo's rule
that load-bearing decisions live in the doc comment of the file that implements
them.

**D-3. The new sheet action names the SCHEDULE, not "supplement settings".**
The destination's supplement header is READ-ONLY by design (PF-5, stated in
`regimen_editor_screen.dart`'s library doc comment) — you cannot change a
supplement's name or dose text there. A row labelled "Supplement settings" or
"Edit supplement" would promise something the screen does not deliver. The
destination's own title is `scheduleTitle`, so the action is
`openSchedule` / en **"Open dosing schedule"**, which lands the user on a screen
whose heading repeats the words they just tapped.

**D-4. Every non-English value is composed from that locale's own existing
words.** No vocabulary is invented for six languages in a quick task:

| key | donor already in the same ARB file |
|---|---|
| `saveChanges` | the save verb that opens that locale's `saveWhilePaused` |
| `openSchedule` | the open verb of that locale's `settingsRemindersOpenSystem` + that locale's `scheduleTitle` noun |

The exact values are tabulated in Task 1 and Task 2. The commit message must
state this derivation — the repo's standing habit for translated copy.

**D-5. A future dose row stays completely inert.** `DoseRow` drops the long
press, the tap AND the custom semantics actions on a future day, and its library
doc comment makes that the guarantee that "closes the write completely — there
is no second path to guard". Re-enabling the sheet on a future row to expose the
editor would mean the sheet has to learn the row state and suppress the mark
rows, which reopens exactly that guarantee. Out of scope. The editor stays
reachable from the Stack tab and from any non-future row of the same supplement.
State the limitation in the doc comment; do not quietly accept it.

**D-6. The new action goes LAST in the sheet, after a `BqSpace.md` gap.** The
mark rows answer "what happened to this dose"; this one leaves the screen. A
larger token gap separates the two intents without adding the separator rule the
sheet's doc comment says it does not have. `BqSpace.md` is already the gap this
file uses between the subtitle and the first action.
</decisions>
