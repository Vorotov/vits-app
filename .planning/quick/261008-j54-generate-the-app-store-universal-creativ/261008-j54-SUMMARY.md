# Quick 261008-j54: the App Store universal creative asset — Summary

`tool/make_store_header.py` generates `store/creative/universal-5244x2950.png`,
one 16:9 master that is valid in both of App Store Connect's optional creative
slots, with the crop-safe region derived in code and the copy checked against
the legal vocabulary gate read out of the Dart test.

## What was built

**Task 1 — the generator** (`14ef641`). `tool/make_store_header.py`, the
sibling of `tool/make_feature_graphic.py` and written in its idiom: same
`make_icons` import, same `font()` helper for the variable Instrument Sans,
same supersample-at-2x-and-LANCZOS ending, same habit of asserting the layout
instead of trusting it.

- The mark is **not redrawn**: `make_icons.draw_mark('3b', mark_h,
  ground=False)`. The V geometry stays in one file.
- The canvas is **RGB from the start**. Apple refuses an alpha channel on a
  creative asset outright — the same rule the Play feature graphic already
  follows.
- The safe area is **derived**, with the arithmetic in the docstring and in
  the code: the 21:9 header crop keeps the full width and leaves
  `5244 / (3840/1646)` = 2248 px of height (76.2%); the 3:2 search crop keeps
  the full height and leaves `2950 * 1.5` = 4425 px of width (84.4%). Only
  their 4425x2248 intersection survives both. Two asserts fail the run if the
  block leaves it, and the margins print.
- Colours restated from `tokens.dart` with the reason in the docstring; a
  Python tool cannot import a Dart file and `tokens.dart` stays the only Dart
  file with a hex literal.
- Optional tagline argv and optional out path, like the sibling.

**Task 2 — written down** (`a97b8d3`). `store/listing.md` gains a **Creative
assets** paragraph in the Apple section: the two slots and their accepted
sizes, that one 16:9 master fills both and why, the crop arithmetic and the
derived safe box, that alpha is refused, that the asset is generated and never
hand-edited, that leaving the slots empty makes Apple fall back to the
screenshots (so it is an improvement, not a prerequisite), and that uploading
is a manual ASC step. A row was added to the Assets table marking it
**built, not yet uploaded**.

`.planning/STATE.md` was updated and **left uncommitted** for the orchestrator:
the last-activity fields, the "store assets are generated" bullet now naming
the third generator, and a fourth item under *Waiting on a human* — upload the
asset by hand in App Information → Creative assets.

## Layout decisions I made

- **Horizontal, not stacked.** Vertical is the tighter constraint (76.2% vs
  84.4%), so the mark sits left and the wordmark plus one line sit right, like
  the feature graphic. A tall stack would spend height the header crop takes
  away.
- **Sizes are fractions of the SAFE height, not the canvas height.** The asset
  is only ever seen cropped, so proportioning it to 2950 would be
  proportioning it to a thing nobody sees. Mark 0.58 of the safe height,
  wordmark 0.27, tagline 0.075 — the same mark-to-wordmark ratio the feature
  graphic uses (0.47 vs 0.45).
- **The block is centred in the canvas**, which makes it centred in both of
  Apple's centre crops. The composition is pixel-identical in all three
  renderings; there is no "the header version" and "the search version".
- The drawn block came out **3544x1304**, leaving **440 px of margin each side
  and 472 px top and bottom** inside the safe box. That is deliberate
  headroom, not a miss: at this canvas size a block filling the safe box would
  read as crude, and the empty paper field is what makes it look like a brand
  header rather than a banner ad.

## Copy and the vocabulary gate

The tagline is **`Plan supplement cycles.`** — the Play feature graphic's own
first line, the approved register. It names no limit, threshold or verdict and
makes no claim about anyone's body.

It is checked **in code**, not by eye: the generator parses
`legalForbiddenStems` out of `test_release/legal_copy_safety_test.dart`,
strips `//` comments first (the `\bcure` entry explains itself with 'secure'
and 'obscure' in quotes, and a naive scan would adopt both as stems — stripping
comments before scanning is this repo's own rule for its source gates), and
asserts no stem matches `VitoMy Plan supplement cycles.`. **28 stems parsed**,
which is the full list, so the assert is not vacuous. Proved both ways: the
real run passes, and `make_store_header.py 'Track your health.'` aborts with
`banned vocabulary ['health']` before anything is rendered.

The `store/listing.md` edit was re-run through the listing validator:
`RESULT: PASS`, vocabulary gate clean across its 46 stems.

**What the three renderings show.** All three are the same composition on the
same paper field: the V mark of two capsules (navy and ochre, split across
their length) on the left, `VitoMy` in accent navy on the right with
`Plan supplement cycles.` in secondary grey below it. The master has generous
paper above and below. The 21:9 crop takes that breathing room off top and
bottom and reads tighter and more banner-like; nothing of the mark or the type
is touched. The 3:2 crop takes paper off left and right, bringing the block
proportionally larger in frame; again nothing clipped — the mark's left edge
and the final period of the tagline both sit well inside. No layout fix was
needed.

## Deviations from Plan

None. The plan was executed as written. Two choices inside its latitude:

- The plan allowed the copy check "in code or by hand"; I did it in code, by
  reading the stem list out of the Dart test, because that is the pattern the
  site's own suite already uses to stop the two from drifting.
- `SEARCH_AR` is written as `1920 / 1280` rather than `1.5`, so both aspect
  constants trace back to a pixel size Apple publishes and a reader can check
  the derivation against the spec page without arithmetic.

## Not done, on purpose

Uploading the asset. App Store Connect has no API path the repo uses for
creative assets; it is a manual step in App Information, recorded in
`store/listing.md` and in STATE.md's *Waiting on a human*.
