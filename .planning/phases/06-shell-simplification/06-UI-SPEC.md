# Phase 6 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope note:** Phase 6 delivers no new *screen*. It rebuilds the app's **chrome** (a hand-built bottom bar, a pushed Settings route, a floating add button) and **subtracts** the editorial-limit layer from the planner. Two of the five ROADMAP criteria are met by deleting code. Authoritative sources: `docs/superpowers/specs/2026-08-17-boostque-v1.1-design.md` §1, §3 (incl. §3.1), §4 — §2 (notifications) is **Phase 7 and out of scope everywhere below** — and `.planning/phases/06-shell-simplification/06-RESEARCH.md`.
>
> **Precedence rule used throughout this contract:** where 06-RESEARCH.md and the spec conflict on a *code fact*, **research wins** and the divergence is stated inline. Two such conflicts exist and both are recorded: (a) the spec's claim that `NavigationBar`'s 80dp height "is not themeable" is **false** — see D-1; (b) the spec says "Сьогодні *gains* the week strip" — it does not, `WeekStrip` is already a child of the Today page (`calendar_screen.dart:104`), so the work is a promotion, not an addition.
>
> **Consumption rule:** the design system is ESTABLISHED (Phases 1-5). All styling goes through `BqColors` / `BqSeriesColors` / `BqRadii` / `BqSpace` / `BqText.mono()` / `bqTheme()` and the existing `BqSegmented`. **This phase adds ZERO new tokens and DELETES one** (`BqColors.thresholdDash`). Every value below is either an existing token referenced by name, or a mockup-exempt component pixel hardcoded in one owning widget under the same locked exemption Phases 1-4 used.
>
> **Discretion resolved:** the spec and research together left three questions open. All three are DECIDED here (§ Discretion Resolved, D-4/D-5/D-6). The planner must not treat any of them as open.

## Screen Contracts

### S8 — `BqNavBar` (NEW widget, `lib/core/widgets/bq_nav_bar.dart`)

```
Container(surfaceAlt fill, 1px hairline top Border, padding: start 22 / end 22)
└─ SafeArea(top: false)                      ← fill + hairline reach the physical edge;
   └─ SizedBox(height: navBarHeightFor(MediaQuery.textScalerOf(context)))
      └─ Semantics(container: true, explicitChildNodes: true, role: SemanticsRole.tabBar)
         └─ Row
            └─ Expanded × 3
               └─ MergeSemantics
                  └─ Semantics(button: true, selected: i == selectedIndex,
                               label: <ARB label>, excludeSemantics: true,
                               onTap: () => onSelected(i))          ← MANDATORY here
                     └─ InkResponse(onTap: …, containedInkWell: false)
                        └─ Column(center, mainAxisSize: min)
                           ├─ Icon(22dp, accent | textFaint)
                           ├─ SizedBox(height: 4)
                           └─ Text(label, 10 / 600|400, maxLines: 1, softWrap: false)
```

- **Height is a function, never a value.** `navBarHeightFor(TextScaler)` is a top-level function in the bar's own file, unit-testable without pumping a widget — the `stripHeightFor` (`week_strip.dart:78`) / `monthCardExtentFor` (`planner_year_grid.dart:101-106`) idiom, transcribed.
- **Its doc comment must record the ACCURATE rationale** (D-1). Writing "the theme cannot express 56dp" would be a durable lie in a codebase that reads its own doc comments.
- **`onTap` sits on the `Semantics` node itself, not only on the `InkResponse`.** `excludeSemantics: true` drops every descendant action — the WR-02 lesson stated verbatim at `week_strip.dart:255-260`. A bar that looks right and cannot be activated by VoiceOver/TalkBack is the failure mode this clause exists to prevent, and it passes every coordinate-tap test.
- **Press feedback: `InkResponse`, chosen deliberately** over the load chart's opacity idiom. The two are both precedented; the bar is the app's primary navigation control and tapping an already-selected tab must still feel like it registered, which an opacity change tied to selection cannot express. Precedent: `planner_year_grid.dart:238-249`. Recorded so a later reader does not "unify" it with the chart.
- **`HitTestBehavior.opaque` over the whole `Expanded` cell**, never the glyph (`week_strip.dart:263-265`).
- If `SemanticsRole.tabBar`/`.tab` proves awkward on the installed SDK, the fallback is `button: true, selected: …` alone — which is what every other bespoke control in this app already uses. **State the downgrade in the doc comment; never let it happen silently.**

## Discretion Resolved

**D-1 — The hand-built bar's rationale, corrected.**
The spec's earlier draft claimed `NavigationBar`'s 80dp height "is not themeable". **That is false**, and the spec itself carries the correction: `navigation_bar.dart:281` resolves `height ?? navigationBarTheme.height ?? defaults.height!`, so `NavigationBarThemeData(height: 56)` would compile. The two accurate reasons, which the widget's doc comment must record instead:
1. **A themed height would still clip.** The resolved height lands in a hard `SizedBox` (`navigation_bar.dart:298`) around a destination stack whose label *does* grow with the text scaler. That is the CR-01 defect class this codebase has already paid for twice (`week_strip.dart:63-77` documents seven bottom overflows at 1.6 and 2.0; `planner_year_grid.dart:5-17` documents the same lesson at the grid).
2. **The height must be a function, not a value.** No `ThemeData` field accepts `double Function(TextScaler)`, and that is exactly the shape NAV-01 requires.
This codebase writes rationale into doc comments, so a wrong rationale is a durable lie — worse than none.

**D-2 — Сьогодні and Календар get distinguishable glyphs.**
The v1 Календар destination uses `Icons.calendar_today*`, which is visually near-identical to the natural Сьогодні glyph. Assigned: Сьогодні → `Icons.today_outlined`/`Icons.today` (a calendar page with one marked day); Календар → `Icons.calendar_month_outlined`/`Icons.calendar_month` (a full month grid). The semantic split is single-day vs. span, which is precisely what the two tabs hold. This **changes the Календар icon** from v1 and supersedes the 01-UI-SPEC icon row. Labels remain the primary distinguisher (the bar keeps labels by locked decision — icon-only is an accessibility and localization regression, and Ukrainian labels are the only thing separating Календар from Сьогодні at a glance).

**D-3 — `tabSettings` is renamed `settingsTitle`.**
It is no longer a tab. `settings_screen.dart:49-50` records the deliberate "one key, two placements" property; the rename **preserves** it (the gear's semantics label and its destination's title) while removing a name that would otherwise lie. Churn is mechanical and confined to `app_shell_test.dart`, `settings_screen_test.dart` and `l10n_device_test.dart`. This codebase does not tolerate names that lie.

**D-4 — The disclaimer rewrite, and why the load chart still needs a caption.**
`plannerDisclaimer` is itself limit copy — current uk names the limit twice (`app_uk.arb:160`). The spec says the disclaimer stays; the *sentence* that stays cannot be this one. Two live assertions constrain the rewrite (`planner_copy_safety_test.dart:261-269`): `plannerDisclaimer.length > disclaimerEducational.length`, and `plannerDisclaimer.contains(disclaimerEducational)`.
**Authored replacement:** uk «Планувальник показує, як ваші цикли накладаються в часі. Освітній матеріал, не медична порада.» · en "The planner shows how your cycles overlap over time. Educational material, not medical advice."
It (a) still carries the educational framing verbatim as its closing clause, so **both assertions keep working unchanged**; (b) still says what the tool is — a description of overlap in time, i.e. a tracking aid — which is the "more important once the app no longer offers any opinion at all" half the spec wanted kept; (c) **asserts no limit**, contains none of `межа`/`меж`/`перевищ`/`норма`, and survives the widened gate; (d) is longer than `disclaimerEducational` in both locales.
Separately: removing `loadAxisLegend` would leave a **self-scaling chart with an invisible ceiling** — a reader who cannot see the denominator will invent one, and the most likely invention is a limit. `loadScaleCaption` («повний стовпчик — увесь стек» / "full bar = your whole stack") states the scale factually and asserts nothing about whether a full bar is good, bad, or anything at all. This is the one place where deleting more copy would make the screen *less* honest.

**D-5 — The Today header layout that cannot overflow.**
See S11. The gear gets its **own end-aligned row above the title**, on all three tabs; the Today title row keeps exactly two children and is left structurally untouched, honouring `calendar_screen.dart:186-189` literally. The rejected alternative — a bounded trailing `Row(mainAxisSize: min)` holding ring + gear — is *probably* safe (both children are text-free geometry) but it makes the header's overflow safety depend on a reader correctly re-deriving "these two are not text", every time anyone edits that row. The dedicated row makes it depend on nothing. The vertical cost is offset by the simultaneous deletion of the always-present `plannerTitle` action row. **Recorded so a later reader does not "tidy" the gear back into the title row.**

**D-6 — Neutral load copy, the week-detail card's remaining content, and two extra key deletions.**
- Neutral count copy: `plannerThisWeek` is kept **verbatim** — it was already a plain count and needed no rewrite; only its `limitBadge` sibling and its colour banding go. The week-detail meta and the week-column a11y label both drop to a bare `substancesCount(load)`.
- The week-detail card keeps **range + count + name chips** and nothing else (S13). Rationale: with the verdict gone, the card's remaining job is "*which* supplements overlap here" — the one question the chart above it cannot answer. Everything deleted was an opinion about that number, never the number itself.
- **`monthMeta` and `yearFootnote` are deleted, not neutralized** — a divergence from research's inventory, stated deliberately. `monthMeta` neutralizes to `"{count}"`, which is a sentence key that *is* its own placeholder; keeping it leaves an empty vessel a future editor can refill with judgement, and `substancesCount` renders identically with one fewer indirection. `yearFootnote`'s entire subject was the red month count and the limit it exceeded, both of which cease to exist; a "neutral rewrite" would be inventing copy the mockup never had. Consequence, accepted: the Рік segment loses a line and closes on `plannerDisclaimer`, exactly as Цикли does. **The plan must re-derive the copy-safety coverage floor from the measured count** — research's "~37" assumed 13 deletions, this contract specifies 16.

## Interaction Contracts

1. **Tapping a nav destination** switches `_selectedIndex` via `setState`. Nothing unmounts, nothing disposes — `IndexedStack` suppresses painting only. Tapping the already-selected destination is a no-op that still shows ink.
2. **Tapping the gear** pushes `SettingsScreen` as a full-screen `MaterialPageRoute`. The nav bar is covered by the route — correct and intended: Settings is no longer a destination.
3. **Popping Settings** (chevron, system back, or edge gesture) returns to the *same* tab, with `_selectedIndex` unchanged and any language change already applied across every open screen.
4. **Tapping the FAB** opens the existing add-supplement sheet, unchanged. A second tap while the sheet is open must not stack a second sheet — verify `showAddSupplementSheet`'s guard rather than assuming it (research E-8).
5. **The FAB is absent on Settings** by construction, not by a flag.
6. **Deep state survives a tab switch** — selected planner segment, selected week, selected month, browsed day. This is now true *by construction*: under the deleted page swap `PlannerScreen` unmounted on every return to Today and its three `autoDispose` providers went with it; as a tab it never unmounts. **Verify, do not rebuild** — `resolvedWeekIndexProvider`/`resolvedMonthIndexProvider` identity-based resolution already handles staleness. ⚠️ Grep `plannerSegmentProvider` in `test/features/planner_screen_test.dart` first: any test asserting the segment *resets* on re-entry is asserting the old bug and must be inverted.
7. **`cyclesModelProvider`/`yearModelProvider` become permanently alive** and recompute on every `stackEntriesProvider` emission even while the user is on Стек. **Accepted; do not gate it.** They are synchronous derivations — no timer, no Drift stream, no materializing path. Gating on `TickerMode` would blank the planner on re-entry and require the hold-last-value machinery for no measured benefit. Recorded as a considered decision so a later reader does not "fix" it.
8. **Nothing this phase adds writes anything.** The FAB opens a sheet; the gear and the chevron navigate. The planner's read-only mandate (04-UI-SPEC) is untouched and its grep gate stays green.
9. **No planner control expresses a verdict.** After this phase, a tap on a week column or a month card changes *which* data is shown and never *how it is judged*.
10. **The system back button on a tab** behaves exactly as in v1 (leaves the app). The `PopScope` back-interception is deleted along with the page swap; nothing replaces it.

## Layout & i18n Rules

- `EdgeInsetsDirectional` only, everywhere new. The FAB uses `FloatingActionButtonLocation.endFloat`, which is direction-aware by construction; the nav bar's destination order flows from `Directionality` through a plain `Row`. No non-directional `EdgeInsets` may enter `bq_nav_bar.dart`, `bq_add_fab.dart`, or any header this phase edits.
- **No fixed vertical extent around text.** `navBarHeightFor(TextScaler)` is the third instance of the `stripHeightFor` idiom in this codebase and must be written in the same shape: two documented constants, one top-level function, a unit test that calls it without pumping. Only the label's line box passes through the scaler — the 22dp icon does not scale, because `Icon` sizes from `IconThemeData`.
- Every user-visible string from ARB, both files in the same commit. `tabToday`, `settingsTitle`, `navBack`, `loadScaleCaption` are new; `emptyStackBody` and `plannerDisclaimer` are rewritten; 16 keys are deleted. **No test in this repo detects an orphaned ARB key** (verified: `arb_parity_test.dart` and `new_language_contract_test.dart` derive from the ARB and self-adjust) — the deletions must be done by hand and reviewed by hand.
- Every `Semantics` node that hides its descendants with `excludeSemantics: true` carries its own `onTap`. This applies to all three nav destinations and to the FAB. A coordinate-tap test passing is not evidence; `SemanticsAction.tap` is.
- `Icon` glyphs are decorative inside a labelled `Semantics` node — never the sole carrier of meaning. The bar keeps its labels for exactly this reason.
- The gear and back controls sit in text-free rows, so no locale can lengthen them. Their semantics labels are ARB-sourced and locale-switch live like everything else.
- Locale propagation into the pushed Settings route is already proven (plan 05-04's bilingual matrix); no new i18n mechanism is introduced.
- `today_screen.dart` enters the `planner_invariants_test.dart` source-glob gates it was never scanned by while it lived inside `calendar_screen.dart` (no raw colour literal, no wall-clock read, no materializing path). That is a **good** outcome, but it may surface pre-existing findings in code that merely moved — treat them as in-scope for this phase, not as regressions.
