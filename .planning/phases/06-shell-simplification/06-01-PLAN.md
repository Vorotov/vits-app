<objective>
Replace the SDK bottom-navigation widget with the hand-built `BqNavBar`, live in `AppShell`, at a 56dp base height that is a function of the text scaler.

This is the phase's **tracer**: the thinnest production-quality path through every layer this phase touches — a new core widget, the shell that hosts it, the theme it stops depending on, the three real destinations it renders, and the assistive-tech activation contract. Nothing about the *destination set* changes here (it stays v1's Стек / Календар / Налаштування, verbatim), so the architectural risk — a computed vertical extent that will not clip at accessibility text scales — is proven end to end on one commit before any deletion work begins.

Purpose: NAV-01. The v1 bar's 80dp fixed height comes from a hard `SizedBox` inside the SDK widget that does not grow with the text scaler; this codebase has already paid for that defect class twice (`week_strip.dart:63-77`, `planner_year_grid.dart:5-17`).
Output: `lib/core/widgets/bq_nav_bar.dart` mounted in `AppShell`, plus its unit/widget test file and an extended bilingual x text-scale matrix.
</objective>

- `lib/core/widgets/bq_nav_bar.dart` — `BqNavBar` widget + top-level `navBarHeightFor(TextScaler)` + two documented extent constants.
- `test/core/widgets/bq_nav_bar_test.dart` — extent-function unit tests, selected/unselected styling, semantics activation, static-render assertions.
- A 2.0 row added to the existing bilingual x text-scale render matrix.

- The `padding: EdgeInsetsDirectional.only(top: 10, ...)` top pad on the bar's outer `Container` — it moves inside the extent formula.
