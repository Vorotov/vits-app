<objective>
Give Settings a way in and a way out that does not depend on being a tab: an end-aligned gear control above the title on every screen the bar reaches, pushing `SettingsScreen` as a full-screen route, and a start-aligned back control on that route.

This lands **before** the destination restructure on purpose. Settings is still a tab for one more plan, so the gear is purely additive and the app is never left with Settings unreachable. Plan 06-03 then removes the destination and the duplicate disappears.

Purpose: NAV-03, first half. A pushed route with no back affordance passes every widget test — tests pop programmatically — and strands the user on the first manual run (research PF-6).
Output: `navBack` copy, a back control on Settings, and three identical gear rows.
</objective>

## Artifacts this plan produces

- ARB key `navBack` — uk «Назад» · en "Back" — in both `app_uk.arb` and `app_en.arb`, plus regenerated l10n.
- A start-aligned back-control `Row` above the Settings body title (`settings_screen.dart`).
- An end-aligned gear `Row` above the screen title on `stack_screen.dart`, the Today page header in `calendar_screen.dart`, and `planner_screen.dart`.
- Widget tests for gear presence, semantics activation, push/pop, and header overflow safety at 1.0 / 1.6 / 2.0 in both locales.

## Artifacts this plan removes

- Nothing yet. This plan is purely additive by design — every deletion in the Settings/navigation area belongs to plan 06-03, which removes the destination, renames the title key and drops the dead bottom padding in one commit.
- Deliberately **not** touched here: `settings_screen.dart`'s `bottom: 84` scroll padding (still correct clearance while Settings is a tab — 06-03 reduces it to `BqSpace.lg` in the same commit that removes the tab) and the planner's `‹ Сьогодні` back control (deleted in 06-03 with the page swap; it coexists with the new end-side gear for exactly one commit).
