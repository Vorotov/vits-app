# Phase 5 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope note:** Phase 5 delivers ONE new screen surface — the **Settings tab** (`Налаштування` / `Settings`), replacing the Phase-1 stub at `lib/features/settings/settings_screen.dart` — carrying exactly one control: the language picker. It also makes three **non-visual amendments** to existing screens (§ Amendments to Existing Screens). No other screen gains or loses a pixel.
>
> **There is no mockup for this screen.** `claude_design_mockup/Boostque v0.1.dc.html` is 991 lines and contains **no Settings surface at all** — its third nav destination is `Радник` (Advisor), verified across all four nav blocks (lines 176, 269, 383, 463); Settings replaced it in the v1 three-tab decision (ROADMAP:31). A case-insensitive search for `settings|налашт|мова|language|укра|english` returns three hits, all false positives (two CSS `font-feature-settings`, one occurrence of `налаштувань` inside regimen-editor prose at line 963). **This screen is therefore COMPOSED from the established design language, not transcribed.** Every geometry and type value below is traced to an existing in-repo screen or to a mockup element being reused by analogy, and the trace is stated in the Source column. Copy is newly authored.
>
> **Consumption rule:** the design system is ESTABLISHED (Phases 1-4). All styling goes through `BqColors` / `BqRadii` / `BqSpace` / `BqText.mono()` / `bqTheme()` in `lib/core/theme/` — tokens are referenced BY NAME. **This phase adds ZERO tokens and ZERO font sizes** (§ Token Additions validates 05-RESEARCH.md A10). Nothing else may introduce a literal (D-07).
>
> **Criterion-4 mandate (load-bearing, and it is a DESIGN constraint, not only an architectural one):** ROADMAP criterion 4 — *"adding a new language requires only one new ARB file with no code changes"*. The visual design is therefore constrained: **no element of this screen may be sized, ordered, positioned, or labelled per-language.** The row list is generated from `AppLocalizations.supportedLocales`; each row's label comes from that locale's own ARB via `lookupAppLocalizations(locale).languageName`. Any fixed row count, any locale-sorted order, any `switch (languageCode)`, any per-language ARB key, and any fixed-height row is a contract violation regardless of how it looks.
>
> **Discretion resolved:** 05-RESEARCH.md flagged 11 ASSUMED items (A1-A11) and 4 Open Questions. Every one that touches the visible product is DECIDED here (sections marked **DECIDED**); the executor implements them as written. UAT may revisit; the planner must not treat any of them as open.

### LOCKED-FONT — the app keeps the platform Cyrillic fallback (Open Question 3, P-10, A6) — **DO NOT "FIX" THIS**

`ThemeData(fontFamily: 'Instrument Sans')` stays exactly as it is (`theme.dart:27`). Instrument Sans carries **no Cyrillic glyphs** — verified twice: upstream declares `subsets: "latin", "latin-ext", "menu"` only (`google/fonts ofl/instrumentsans/METADATA.pb`), and a direct `cmap` parse of the bundled `assets/fonts/InstrumentSans[wdth,wght].ttf` confirms `Ц ц ї і І Ї є ґ` are all absent. Ukrainian text therefore renders from the platform fallback (SF on iOS, Roboto on Android) while Latin letters and **digits** on the same line render from Instrument Sans.

**This is the mockup-faithful answer and it is now locked for v1.** The approved HTML mockup was itself rendered in a browser where Instrument Sans has no Cyrillic — *the Ukrainian screens the user approved ARE this fallback rendering.* Consequences that are ACCEPTED, not defects:

- Mixed-family lines (`Омега-3`, `5 мг`) with differing x-heights and advance widths.
- Rendering differs between iOS and Android.
- All mono text is unaffected — JetBrains Mono covers full Ukrainian Cyrillic (cmap-verified).

**Forbidden remediations** (each would be a contract violation, not an improvement): swapping the primary family to Manrope/Inter/Noto Sans; adding a `fontFamilyFallback` (worst of both — still mixes families inside a line *and* pays the bundle cost); adding `google_fonts` (never-use, offline app). This closes the Phase-2 carried todo in `.planning/STATE.md` — record it in the phase SUMMARY as a **locked decision**, so v1.x does not re-litigate it. Revisiting it later invalidates the Phase-4 gantt truncation measurements (156.0px allotted / 183.1px intrinsic) and requires a full re-run of the text-scale matrix.

## Copywriting Contract

All copy ships as ARB keys in `app_en.arb` + `app_uk.arb` in the same commit. This screen has **no mockup copy to transcribe** — all three keys are newly authored and therefore `[ASSUMED]` until UAT (05-RESEARCH.md A2). Voice lexicon locked in Phase 2; no effect promises, no guilt-framing, no medical claim — none of which this screen has any occasion to make.

**Reused existing key (do NOT duplicate):** `tabSettings` — uk "Налаштування" · en "Settings". **One key, two placements:** the nav-bar destination label and this screen's title, so the tab and its screen can never disagree (the Phase-4 `plannerTitle` precedent).

**Three new keys — and the asymmetry between them is load-bearing:**

| Key | uk | en | Resolution path |
|-----|----|----|-----------------|
| `languageName` | `Українська` | `English` | **`lookupAppLocalizations(thatLocale).languageName`** — each ARB declares its OWN endonym under this same key. A language's name is written in that language. **Never translate this key**; never add `languageNameUk`-style per-language keys; never a `switch`/`Map` of codes → names. This single decision is what keeps criterion 4 true (05-RESEARCH.md P-2, option B) |
| `languageSystem` | `Системна` | `System default` | **`context.l10n.languageSystem`** — rendered in the ACTIVE locale, because it names a *mode*, not a language |
| `settingsLanguageTitle` | `МОВА` | `LANGUAGE` | `context.l10n` — mono eyebrow, stored uppercase |

Required `@`-metadata in the template (`app_en.arb`), because these are the keys most likely to be "helpfully" refactored by a future reader:

```jsonc
"@languageName": {
  "description": "This language's OWN name, written in this language (its endonym). EVERY app_*.arb declares its own value under this same key; the picker resolves it via lookupAppLocalizations(locale), so adding a new ARB file needs no code change (L10N-04, criterion 4). NEVER translate this key."
},
"@languageSystem": {
  "description": "Language-picker option meaning 'follow the device language'. Rendered in the ACTIVE locale via context.l10n, unlike languageName."
},
"@settingsLanguageTitle": {
  "description": "Mono eyebrow above the language list on the Settings screen, in the supplementsLabel style. Stored uppercase; never toUpperCase()'d at runtime."
}
```

| Element | Copy |
|---------|------|
| Screen title | `tabSettings` — uk "Налаштування" · en "Settings" (reused) |
| Section eyebrow | `settingsLanguageTitle` — uk "МОВА" · en "LANGUAGE" |
| First row (always) | `languageSystem` — uk "Системна" · en "System default". Plain, with **no parenthetical resolved language** — DECIDED-6 |
| Language rows | Each locale's own `languageName`, in generated order |
| **Primary CTA** | **This screen has no button CTA and no form.** Its primary interaction is *selection* — a tap on a bounded list of rows. There is no "Save", no "Apply", and no "Done": the selection IS the commit (DECIDED-7) |
| Empty state heading / body | **Not applicable — and none may be authored.** The list can never be empty: it always renders `1 + N` rows with `N ≥ 1` (the template ARB `app_en.arb` is a build requirement). An empty-state string here would be dead copy that no test could ever reach |
| Error state | **Not applicable — and none may be authored.** This screen has no provider that can fail: `AppLocalizations.supportedLocales` is a compile-time `const` and `LocaleController` is a synchronous `Notifier<Locale?>`. ## Screen Contracts

### S7 — Settings screen (NEW — replaces the Phase-1 stub)

**Structure** — `Scaffold` > `SafeArea` > `ListView` (never a `Column`: at textScaler 2.0 with several languages the content exceeds the viewport, and a `Column` would overflow). **No `AppBar`** — the title lives in the body, matching Stack, Calendar and Planner.

```
ListView(padding: EdgeInsetsDirectional.only(start: 20, end: 20, top: BqSpace.lg, bottom: 84))
├─ Text(tabSettings)                      headlineSmall
├─ SizedBox(18)
├─ Semantics(header: true, Text(settingsLanguageTitle))   BqText.mono(10.5, textMuted, ls .63)
├─ SizedBox(10)
└─ _LanguageCard                          surface · 1px cardBorder · BqRadii.card · clipBehavior: antiAlias
   ├─ _LanguageRow(null)                  ← "System default", ALWAYS first
   ├─ Divider(1px, hairline, full-bleed)
   ├─ _LanguageRow(supportedLocales[0])
   ├─ Divider(1px, hairline, full-bleed)
   └─ … one row per AppLocalizations.supportedLocales, in GENERATED order
```

**Row list construction — the criterion-4 core:**

```dart
final options = <Locale?>[null, ...AppLocalizations.supportedLocales];
```

- `null` first, always (DECIDED-1). It is the default state, and putting it first means the list's ordering never depends on a locale-sensitive string sort.
- The rest in **generated order**, which `preferred-supported-locales: [en]` in `l10n.yaml` now controls. **Do NOT sort by display name** — a locale-sensitive `compareTo` would make row order depend on the active language, and the fallback language should read first.
- The card's row count is `options.length` and nothing else. No `if (code == 'uk')`, no fixed count, no per-language spacing.

**`_LanguageRow` anatomy** (`InkWell` > `ConstrainedBox(minHeight: 52)` > `Padding(14/14)` > `Row`):

| Slot | Widget | Rule |
|------|--------|------|
| Label | `Expanded(Text(label))` | **Wraps; never `maxLines`, never `TextOverflow.ellipsis`, never a fixed width or height.** A long endonym at scale 2.0 flows to a second line and the row grows with it (WR-04 / CR-01 lesson) |
| Gap | `SizedBox(width: 12)` | |
| Mark | `ExcludeSemantics(Text("✓"))`, non-flexible, rendered only when selected | Instrument 15/600 `accent`. When unselected the slot renders **nothing** (not a transparent placeholder) — the label simply gets the full width |

- `label` = `locale == null ? l10n.languageSystem : lookupAppLocalizations(locale).languageName`.
- `selected` = `locale?.languageCode == ref.watch(localeControllerProvider)?.languageCode`. Exactly one row is selected at all times; a stored code outside the shipped set sanitizes to `null`, which checks the System row — never zero checks, never two.
- `onTap` = `ref.read(localeControllerProvider.notifier).setLocale(locale)` — including on the already-selected row (idempotent, harmless).
- Whole-row `HitTestBehavior.opaque` hit area; the ✓ is never independently tappable.

**Accessibility (WR-02 lesson — actions go ON the Semantics node, never on a descendant):**

```dart
Semantics(
  container: true,
  inMutuallyExclusiveGroup: true,   // announces as a radio group member
  checked: selected,
  label: <the row's visible label>,
  onTap: <select>,
  child: ExcludeSemantics(child: <the InkWell subtree>),
)
```

- **`button: true` is deliberately NOT set** — a mutually-exclusive option is a radio, not a button, and `inMutuallyExclusiveGroup` + `checked` is what makes VoiceOver/TalkBack announce "selected/not selected" rather than "button".
- The ✓ glyph is excluded from semantics: its meaning is already carried by `checked`, and announcing a bare "✓" would double-speak the state.
- The eyebrow carries `Semantics(header: true)` so AT users can jump to the section; the screen title inherits `headlineSmall` and needs no extra annotation beyond the existing convention.

**No loading surface, no error surface, no empty surface, no spinner** — see UI Considerations #3, #4, #5.

## Amendments to Existing Screens (no new visuals)

These are Phase-5 work that touches already-approved screens. **None of them changes a single pixel of layout, color, or copy geometry** — they change *when* an already-designed surface appears, and one a11y string. They are listed here so the executor does not treat them as redesigns.

### A1 — The designed error surface must win over the loading surface (P-9, closes the Phase-4 carried todo)

Riverpod 3 reports a failing provider as an `AsyncLoading` that **carries** the error while it retries on its own backoff (`riverpod-3.4.2/element.dart:790-797`), and `AsyncValue.when` defaults `skipLoadingOnReload: false`, so `loading()` wins for the full `defaultRetry` window — **≈38.2 seconds** (200+400+800+1600+3200+6400×5 ms). During that window three screens render a *blank* body instead of the error surface those screens already have designed and localized.

**Design ruling: "has an error" beats "is loading", at all three surfaces.** Auto-retry stays enabled (it genuinely self-heals a transient failure); what changes is the rendering rule.

| Screen | Existing designed surface | Amendment |
|--------|---------------------------|-----------|
| `stack_screen.dart:103-155` | `stackLoadError` + `retry` | add `skipLoadingOnReload: true` to the `.when(...)` |
| `calendar_screen.dart:312-370` | day-view error surface | same |
| `planner_screen.dart:608-613` | `plannerLoadError` + `retry` | reorder the `switch` so `AsyncValue(hasError: true)` is the FIRST arm |

Visual contract, restated as a truth the checker can hold: **on all three screens the designed error copy + `retry` button must be on screen within ONE frame of the failure** — never a blank body, never a spinner, never raw exception text. Prove it with the retry timers *live* (`tester.pump()`, never `pumpAndSettle` — PF-7).

### A2 — One concatenated a11y label becomes a two-placeholder key (PF-5)

`add_supplement_sheet.dart:356` composes `label: '${l10n.addSupplement}: ${entry.name(l10n)}'` — the only concatenation of localized fragments in the codebase. It hardcodes word order and the `: ` separator across every language. Replace with a single ARB key carrying two placeholders, following the in-repo `weekLoadLabel` / `cycleSummaryCyclic` convention ("pass the finished string in"). **Semantics label only — no visible change.**

### A3 — Locale-independent sentence casing (PF-6)

`calendar_screen.dart:232-236`'s hand-rolled `_capitalizeFirst` is swapped for `intl`'s `toBeginningOfSentenceCase(value, locale)`. Correct-but-lucky for uk/en today; wrong for `tr`/`az` — exactly the class of bug criterion 4 invites. **Zero visual change in either shipped locale**, and `month_names_test.dart` catches it instantly if the output differs. The four `toUpperCase()` sites on already-uppercase-safe abbreviations (`planner_year_grid.dart:163`, `planner_month_detail.dart:120`, `planner_gantt.dart:155`, `week_strip.dart:278`) are **left alone in v1** — recorded here as a known constraint, not a task.

## Discretion Resolved

**DECIDED-1 — v1 Settings content is: title, eyebrow, language card. Nothing else. (Open Question 1, A1)**
*Basis:* the approved design spec scopes the directory literally — `settings/     # language picker (grows later: profile, export, etc.)` (`docs/superpowers/specs/2026-08-14-boostque-v1-design.md:56`). REQUIREMENTS marks export/import (EXPT-01) v1.x and notifications (NOTF-01) v2. No requirement in L10N-01..04 asks for anything but the picker.
*Two candidates were considered and both are REJECTED for v1:*
- **App version / About line — REJECTED.** Reading the real version requires `package_info_plus`, and this phase's hardest constraint is **zero new packages**; the only alternative is a hardcoded string that silently drifts from `pubspec.yaml` — a lie on a screen whose entire job is to be truthful about configuration. Additive later, at the cost of one package, in a phase that is allowed to add one.
- **Educational disclaimer — REJECTED.** PLAN-04 binds the disclaimer to *planner* screens, because that is where an editorial limit is asserted. Settings makes no health claim, shows no supplement data, and displays no number; putting the disclaimer here would dilute it into boilerplate on the one screen where it means nothing. `disclaimerEducational` does not appear in `features/settings/`.
*Extension point, so the next phase does not have to invent one:* a second section = a second mono eyebrow + a second card, at the same 18/10 rhythm. The screen is already a `ListView`.

**DECIDED-2 — A vertical checked list, not `BqSegmented`, not chips.**
`BqSegmented` is a fixed-width horizontal control (`bq_segmented.dart:21-23`, "supports any number of segments (2+)"). A language list grows **vertically and unboundedly** and carries long native names ("Українська", "Português brasileiro") — a segmented control would either clip them or force a per-language width, and both are criterion-4 violations. A checked list scales to N languages at any text scale with no code change; a segmented control does not.

**DECIDED-3 — Inline on the Settings screen: not a pushed page, not a bottom sheet. (Research's "Claude's Discretion")**
*Rationale, and it is criterion-driven rather than aesthetic:* criterion 3 requires the change to apply **instantly across every open screen**. With an inline list the user's own finger stays on the screen that re-renders — the title, the eyebrow, and the nav-bar labels below all flip language in the same frame as the ✓ moves. A pushed page or a modal sheet **occludes the app**, so the user must dismiss it to observe the very thing the criterion promises, and the sheet would have to re-localize itself mid-gesture (E-10) for no benefit. Secondary reasons: one fewer route/surface to build, localize, and test; and a bounded list of 2-3 rows does not earn a navigation step.
*Also rejected:* `RadioListTile` / `ListTile`. They come with Material's own paddings, minimum heights, and dense/visual-density behaviour that would need a fresh `ListTileTheme` to match the mockup's card idiom — more theme surface than the hand-built row it would replace, and a fixed `minVerticalPadding` regime that fights the text-scale rule.

**DECIDED-4 — Selection is signalled by ✓ AND weight, never by color alone.**
Unselected: label 15/400. Selected: label 15/600 **plus** a trailing `accent` "✓". Two redundant, non-color channels (glyph presence + weight), so the state survives a color-vision deficiency and a grayscale screenshot. Rejected: an accent-tinted row fill (reads as a chip, DECIDED under Token Additions), a leading radio circle (would introduce the screen's only circular affordance and a fourth column), and color-only differentiation (WCAG 1.4.1 failure).

**DECIDED-5 — Full-bleed 1px `hairline` dividers between rows.**
An inset divider implies a leading icon/avatar column this list does not have. Full-bleed reads as one continuous control group, which is exactly what a mutually-exclusive option set is. The card is `clipBehavior: Clip.antiAlias` so the first and last row's ink ripple respects `BqRadii.card`.

**DECIDED-6 — "System default" ships PLAIN, with no parenthetical resolved language. (Open Question / A3 — REVERSES the research's tentative recommendation)**
05-RESEARCH.md P-7 floated `Системна (Українська)`. **Rejected, on a correctness argument the research did not carry through:** the obvious implementation reads `lookupAppLocalizations(Localizations.localeOf(context)).languageName`, and `localeOf` returns the **ACTIVE** locale — which equals the override whenever one is set. A Ukrainian-device user who overrides to English would see "System default (English)", stating the exact opposite of the truth. Making it correct requires independently re-running `WidgetsApp.basicLocaleListResolution` over `platformDispatcher.locales`, i.e. a *second* implementation of locale resolution living in a widget, which can silently disagree with the framework's own — a real bug risk traded for a parenthetical.
*And the information is not lost:* the row names a **mode**, and selecting it answers the question within one frame, reversibly. Raise the wording at UAT as a copy question — never restore the parenthetical without also moving resolution off `localeOf`.

**DECIDED-7 — Switching the language shows NO confirmation and NO feedback chrome.**
No snackbar, no dialog, no toast, no "Language changed" banner, no "Save"/"Apply" button. *Rationale:* the entire UI re-rendering in the new language **is** the feedback — it is total, immediate, and impossible to miss; a snackbar would be a second, redundant signal that would itself render in the new language and would **occlude the very rows the user is reading**. The action is non-destructive and instantly reversible by tapping another row, so it fails every test for needing a confirmation step. Rapid repeated taps need no queue or lock: each `setLocale` sets state synchronously and awaits its own write; last write wins (E-15).

**DECIDED-8 — This screen has no async surface, and a failed persist is deliberately silent.**
Both facts follow from the state model, and both are stated because Phase 4 taught the opposite lesson elsewhere (A1 above):
- `AppLocalizations.supportedLocales` is a compile-time `const` and `LocaleController` is a synchronous `Notifier<Locale?>` — **nothing on this screen can be in `AsyncLoading` or `AsyncError`.** Therefore no spinner, no error copy, no retry button may exist in `features/settings/`. This is not an oversight to be "fixed" by a reviewer who has just read the A1 amendment.
- `setLocale` sets `state` **first** and persists **after** (PF-3 — persisting first makes "instantly" a lie by putting a platform-channel round-trip and a disk write in front of the repaint). If the `shared_preferences` write throws, the user sees the new language for this session and the *next* launch reverts. **That failure is not surfaced.** Surfacing it would mean an error banner about a setting that visibly *did* take effect — more confusing than the silent, self-correcting behaviour, and the alternative (a UI that stalls on disk) is strictly worse.
- **Flash-free bootstrap (Open Question 2, A4): SHIP IT.** `LocaleController.build()` seeds synchronously from an injected `sharedPreferencesProvider`, so a user who set an override never sees a system-language frame on cold start. If the plan instead falls back to the async load, the *visual* contract still holds and must be honoured: the picker renders on frame 1 with **System default checked** and flips to the stored row when the load settles — it may **never** render a spinner or a blank card while waiting.

## Interaction Contracts

1. **Tap any row** → that language becomes active **within a single frame**: the ✓ moves, the label weights swap, the screen title, the eyebrow and the three nav-bar labels re-render, and both other tabs (kept mounted by the `IndexedStack`, `app_shell.dart:38-45`) are already re-localized when the user switches to them. Provable with `tester.pump()`, never `pumpAndSettle` (PF-3's warning sign).
2. **Tap the already-selected row** → no visible change; the write is idempotent. Not an error, not a toggle-off.
3. **Tap "System default"** → the override is cleared, the app immediately renders the system-resolved language (English on any unsupported system language), and the next launch follows the system.
4. **Nothing on this screen writes to the database.** `features/settings/` never imports `IntakeRepository`, `SupplementRepository`, `RegimenRepository`, `dayDosesProvider`, or `ensureLogsForDay`. The only write in the whole feature is one `shared_preferences` key, `app_locale` (locked: `shared_preferences` has exactly one job in this app).
5. **No gesture other than tap.** No long-press, no swipe, no drag, no reorder, no context menu.
6. **Tap targets:** every row is ≥52px tall and full-width — comfortably past 44pt, and the Phase-4 14px-column compromise is explicitly not repeated here.
7. **Pressed state:** default Material ink ripple, clipped to the card's radius. No elevation, no scale, no color-shift on press.
8. **Propagation beyond this screen:** a locale change re-localizes a pushed route (the regimen editor) and any open modal sheet (add-supplement, dose-action) in place, because their routes sit below `MaterialApp`'s `Localizations` — including `showDatePicker`/`showTimePicker` chrome via `GlobalMaterialLocalizations` (E-10, E-11, V-6).
9. **What does NOT re-localize, by design:** supplement names already in the user's stack. Catalog entries copy the active locale's name at add-time (`catalog.dart:11-15`) — switching to English does not rename "Магній". **State this at UAT so it is not filed as a bug** (E-12).
10. **Back / navigation:** none. Settings is a root tab with no sub-route; the system back button behaves exactly as on Stack (leaves the app), unchanged from Phase 1.

If the async-load fallback is taken (DECIDED-8), the picker still renders fully on frame 1 with System default checked, and never shows a spinner while the stored value settles.
4. **E1/E2/E3 error:** no provider on this screen can fail, so **no error surface may be authored** — no error copy, no retry button, no exception text. A failed `shared_preferences` write is silent by design; `setLocale`'s state-first ordering means the visible language is the in-memory truth for the whole session (DECIDED-8).
5. **E3 zero-one-many:** the row count is derived, not written. With one shipped language the card renders 2 rows; with three it renders 4; adding `app_pl.arb` adds a row and its label with **zero** change in `features/settings/`. No file under `features/settings/` may contain a language code, an endonym literal, or a `switch`/`Map` over locales (grep gate).
6. **E3 partial / selection invariant:** exactly one row is checked at all times. A stored `app_locale` outside the shipped set — a tampered value, or a code whose ARB was removed — sanitizes to `null` and checks the "System default" row. Never zero checks, never two, never a `lookupAppLocalizations` throw (threat T-01-07; E-7).
7. **E3 long-text / overflow:** the row label is `Expanded` and **wraps** — no `maxLines`, no ellipsis, no fixed width, and **no fixed height anywhere in the row** (`ConstrainedBox(minHeight: 52)`, never `SizedBox(height:)`). The trailing ✓ is non-flexible. 8. **E1/E4 static content:** the title uses `headlineSmall` verbatim and the eyebrow `BqText.mono(10.5, …)` verbatim; neither sits in a fixed-width or fixed-height box, and both wrap. The eyebrow is `Semantics(header: true)`.
9. **E3 interaction:** tapping a row applies the language within one frame across this screen, the nav bar, both other tabs, any pushed route and any open sheet — with **no** snackbar, dialog, toast, "Save" button or restart prompt (DECIDED-7). Tapping the selected row is a no-op.
10. **E3 accessibility:** the row IS the semantics node — `inMutuallyExclusiveGroup: true` + `checked:` + `label:` + `onTap:` sit on the row, never on a descendant, and the subtree is `ExcludeSemantics`-wrapped (the WR-02 lesson from `week_strip.dart:262-268`). The ✓ glyph carries no semantics of its own. Selection is legible without color (✓ presence + 400→600 weight).
11. **Text-scale invariant:** at textScaler 1.0 / 1.6 / 2.0 in **both** locales the Settings screen throws no layout exception (`tester.takeException()` is null), and while `en` is active no Cyrillic character (`RegExp(r'[Ѐ-ӿ]')`) appears in any rendered `Text` — except `languageName` for a Cyrillic-script locale, which is legitimately Cyrillic in any active language and is the one explicit allowlist entry (A8).
12. **E5 amended async surfaces (§ A1):** on Stack, Calendar-day and Planner, the already-designed error copy + `retry` button are on screen **within one frame** of a provider failure — never a blank body, never a spinner, never raw exception text — with Riverpod's default retry live. ## Layout & i18n Rules

- `EdgeInsetsDirectional` only; **not one fixed-width or fixed-height container around any `Text` on this screen.** uk endonyms and en labels differ in length, and a future ARB may bring a much longer one — the row must accommodate it without a code change (criterion 4 applies to *layout*, not just to strings).
- Every user-visible string from ARB keys, both files in the same commit. This screen introduces **no plural key** — nothing here is counted — so the four-form uk CLDR obligation adds no work, and none may be invented.
- `languageName` is resolved with `lookupAppLocalizations(locale)`, `languageSystem` and `settingsLanguageTitle` with `context.l10n`. **The asymmetry is the design.** In-repo precedent for the synchronous lookup: `catalog.dart:158`.
- Uppercase eyebrow text is stored uppercase in the ARB, never produced by `toUpperCase()` at runtime — side-stepping PF-6's locale-independent-casing trap (`tr`/`az`).
- **Formatters and `context.l10n` are read inside `build`, never in `initState` and never into a `late final` field** (PF-4). The codebase currently has zero such caches across all 17 `DateFormat` sites; this screen must not be the first.
- The list order comes from the generated `supportedLocales`, whose order is now **declared** in `l10n.yaml` (`preferred-supported-locales: [en]`) rather than inherited from alphabetization — the fallback language is `supportedLocales.first`, and without the declaration adding `app_de.arb` would silently make German the app's fallback (PF-1). The picker must never re-sort it.
- Scroll body pads bottom ≥84px to clear the nav bar (locked from Phase 2).
- **RTL readiness is unchanged and unclaimed:** the widget layer is grep-clean of LTR-hardcoded geometry and this screen adds none. The four existing `CustomPainter`s still paint left-to-right in raw canvas coordinates (E-9) — a known, recorded v1 constraint, out of scope here.
- **Boundary of criterion 4, stated honestly:** "one new ARB file" holds **for any of the 82 languages `flutter_localizations` covers** (`kMaterialSupportedLanguages`). Outside that set, Material chrome is untranslated and `GlobalMaterialLocalizations.load` asserts in debug. That is the shape of the guarantee, not a defect — pin it with a test rather than leaving it to be discovered (V-3 assertion 5, PF-9).
