## Screen Contracts

### S4 — Calendar / Today screen (mockup screen 02, lines 193-274)

**Header (fixed, above the scroll body — never scrolls away):**
- Title row: title column (title + 4px + subtitle) on the start side, `DayProgressRing` on the end side, 10px gap, baseline-aligned to the mockup's `align-items:flex-end`.
- Title text: `calendarTitleToday` when the resolved day == today; otherwise the capitalized weekday via `DateFormat('EEEE', locale)`.
- Subtitle: `DateFormat('EEEE, d MMMM', locale)` when today (uk "четвер, 13 серпня"); `DateFormat('d MMMM', locale)` otherwise (avoids repeating the weekday already in the title). Pin the uk rendering with one unit test (A7).
- `backToToday` text button replaces nothing — it renders inline after the subtitle (start-aligned, 8px gap) ONLY when the resolved day ≠ today; tapping it clears `selectedDayProvider` to null.
- `WeekStrip` 16px below the title row.

**Week strip:** a `PageView` of week pages; each page is a `Row` of 7 `flex: 1` cells, gap 5, Monday-first in every locale (DECIDED-4). Cell: radius `BqRadii.dayCell`, padding 9/10, centered column [dow mono 10/400 → 6px → day number 14/500 → 7px → 4px dot]. Cell states:
- today → fill + border `accent`; number `surface`; dow + dot `onAccentMuted`.
- selected non-today → fill `surface`, 1.5px `accent` border, number `ink`, dow `textFaint`.
- other → fill `surface`, 1px `cardBorder`, number `ink`, dow `textFaint`.
- Dot: `calm` when that day is in the past AND every dose it has is non-pending (fully handled); `field` otherwise (including future days, days with zero doses, and days whose summary has not resolved yet).
- Paging: swipe back up to 52 weeks; forward capped at the week containing today. Tapping a cell sets `selectedDayProvider`; tapping today's cell clears it to null.

**Scroll body** (`padding 18/20/84`):
- Non-empty time blocks only, in block order Ранок → День → Вечір → Ніч, 18px apart. A block with zero doses is omitted entirely (DECIDED-1).
- Block header row (gap 10): [time mono 13/500, tnum — the **earliest real slot time in that block**, not the mockup anchor] · [label 12.5/500 `textSecondary`] · [1px `cardBorder` flexible divider] · [tag chip, mono 11/400, radius `BqRadii.chip`, padding 4/7].
- Block tag resolution (in order): all doses taken → `blockAllTaken`, `calm` on `calmBg`; all doses marked with ≥1 skipped → `blockAllMarked`, `textSecondary` on `chip`; **today only** and the block is past with ≥1 pending → `blockProgress` ("{taken} з {total}"), `warn` on `warnBg`; otherwise → the block's meal tag, `textMuted` on `chip`.
- Dose rows 7px apart. Row anatomy: radius `BqRadii.doseRow`, padding 13/14, [24px circle] + 12px + [column: baseline row (name 14.5/500 · 7px · amount mono 11.5/400 `textFaint`) → 7px → `Wrap` of chips, 6px gaps].
- Row visual states — exhaustive table; no other combination may render:

| State | Circle | Name | Row fill | Row border | Extra chip |
|-------|--------|------|----------|-----------|-----------|
| pending (today, not yet due, or any future day) | 1.8px `checkBorder`, fill `surface`, no glyph | `ink` | `surface` | `cardBorder` | — |
| overdue (**today only**: pending and slot time < now) | same as pending | `ink` | `surface` | `warnBorder` | `overdueLabel`, `warn` on `warnBg` |
| taken | 1.8px `calm`, fill `calm`, "✓" `surface` 12/600 | `textMuted`, line-through | `surfaceAlt` | `cardBorder` | — |
| skipped | 1.8px `inputBorder`, fill `chip`, "−" `textSecondary` 12/600 | `textMuted`, line-through | `surfaceAlt` | `cardBorder` | `skippedLabel`, `textSecondary` on `chip` |

- Pressed state: row border → `accentBorder` (mockup `style-hover`). Default Material ink ripple retained; no elevation.
- Disclaimer line (`calendarDisclaimer`) closes the body, 16px below the last block, 4px horizontal inset.
- Empty day (zero doses): blocks, ring, and disclaimer-adjacent content collapse to a centered-start empty block (`emptyDayTitle` + 8px + body variant) in the same 20px-padded column; **the disclaimer still renders** below it.

## Discretion Resolved (the four ASSUMED items + three Open Questions)

**DECIDED-1 — Time-block boundaries (A1/A2, RESEARCH P-4).**
Boundaries are locked as a single const `blockStartsMinutes = [0, 720, 1080, 1320]`: Ранок 00:00-11:59, День 12:00-17:59, Вечір 18:00-21:59, Ніч 22:00-23:59. Rationale: every default the Phase-2 editor can produce lands in the intuitive block (08:00 and 10:30 → morning; 13:00 and 16:00 → day; 19:00 and the 21:00 fallback → evening; 22:00 and 22:30 → night), and a post-midnight dose (00:00-03:59) belongs to the day it is logged on, so folding it into "Ранок" keeps the block list in chronological order — a separate "після півночі" block would sort last while displaying first. Block header time = the **earliest real slot time in the block** (not the 08:00/13:00/19:00/22:00 mockup anchors): the anchors are Phase-2 editor defaults, and printing "08:00" above a 09:30-only block would be false information. Empty blocks are hidden.

**DECIDED-2 — Skip gesture and undo affordance (A3, RESEARCH P-7 / Open Question 3).**
- **Tap** on a dose row toggles `pending ↔ taken` — mockup-exact (`tog`, line 687) and literally one tap for the dominant action and for undoing it (TRACK-02).
- **Long-press** opens the S5 dose action sheet with explicit, labeled `markTaken` / `markSkipped` / `undoMark` rows.
- Rejected alternative: a bare long-press that silently toggles `pending ↔ skipped` (the research recommendation). Reasons: an invisible gesture with no label is undiscoverable, has no screen-reader equivalent, and gives "skipped" no visible undo path — while TRACK-02 requires undo of *the mark*, not just of "taken". Rejected alternative: a trailing per-row skip control — it adds chrome to a row the mockup deliberately keeps to circle+text+chips.
- Accessibility parity: the row exposes `markTaken` / `markSkipped` / `undoMark` as Semantics custom actions, so no function is reachable only by long-press.
- No SnackBar-undo: the row itself always shows the current state and the inverse gesture is one tap away; a timed undo queue would add state with no benefit. `markFailed` is the only SnackBar on this screen.
- Transition table (the view computes `next`; the repo accepts any status):

| Current | Tap → | Sheet: taken | Sheet: skipped | Sheet: undo |
|---------|-------|--------------|----------------|-------------|
| pending | taken | taken | skipped | (hidden) |
| taken | pending | (hidden) | skipped | pending |
| skipped | taken | taken | (hidden) | pending |

**DECIDED-3 — Missed / past-day styling (A4, RESEARCH P-6).**
A past day's unmarked dose renders in the **pending visual** (empty `checkBorder` circle, name in `ink`, `surface` fill, `cardBorder` border) plus one neutral chip `notMarkedLabel` ("не позначено") in the `chip`/`textSecondary` palette. No `warn` color, no `risk` color, no red/amber border, no strikethrough, no muted "dead" name — the row stays visually live because it **remains tappable**: marking a dose taken late is a legitimate correction, and undo returns it to pending/missed. Rationale for the copy choice over the research's "пропущено": the DB row is `pending`, so the app genuinely does not know what happened; "не позначено" states only what is true, carries no blame (TRACK-03), and leaves "пропущено" free to mean the user's own deliberate skip. Nothing is ever aggregated — no counts, no streaks, no history rollup (HIST-01 is out of scope).

**DECIDED-4 — Week-strip navigation depth (A6, RESEARCH P-9 / Open Question 1).**
The strip is a horizontally-swipeable `PageView` of weeks: **back up to 52 pages** (one year — a finite `itemCount`, so no unbounded builder), **forward capped at the week containing today**. Future days *within* the current week remain reachable and render as plain pending rows with no overdue/missed styling (E-10); weeks beyond that are unreachable — forward planning belongs to Phase 4's planner views. Weeks are **Monday-first in every locale** (mockup order, uk convention) rather than `MaterialLocalizations.firstDayOfWeekIndex`, which would flip en-US to Sunday and diverge from the approved visual. No chevrons: the strip is the affordance and the `backToToday` button is the escape hatch. `selectedDayProvider` is nullable with `null` = "follow today", so sitting on today across midnight auto-advances (RESEARCH P-3).

**DECIDED-5 — Overdue styling on today ships mockup-exact (Open Question 2).**
The amber `не прийнято вчасно` chip and `warnBorder` row border ship as drawn (lines 727-733), and past blocks of today show the `{done} з {total}` warn tag. This is the approved visual, it reads as "still actionable today" rather than as a failure record, and it never accumulates. The neutrality mandate is honored where it was written — **past days**, which use no warn color at all.

**DECIDED-6 — Block tag when a block contains skips (E-6).**
`blockAllTaken` ("усе прийнято", calm) fires only when every dose in the block is `taken`. A block where every dose is marked but at least one is `skipped` shows the neutral `blockAllMarked` ("усе відмічено") on `chip` — honest (it does not claim they were taken) and non-warn (the user handled it deliberately). The warn `{done} з {total}` tag is reserved for a past block of **today** that still has pending doses.

**DECIDED-7 — Ring on empty and on browsed days (A5/A8, E-7).**
The ring renders for whichever day is resolved, using that day's counts (`taken` vs all doses; skipped counts as not-taken, mockup formula line 716). At `total == 0` the ring is **not rendered at all** — a "0/0" ring is meaningless chrome, and the empty-day copy carries the message instead.

## Interaction Contracts

1. **Tap a dose row** → toggle `pending ↔ taken` via `setStatus`; the `watchDay` stream re-emits and the row re-renders. No local optimistic state.
2. **Long-press a dose row** → S5 action sheet (DECIDED-2). Screen readers reach the same three actions via Semantics custom actions.
3. **In-flight guard (PF-4):** a row ignores all gestures while its own `setStatus` future is pending, and computes `next` from its currently rendered status — never from a captured stale value. No spinner is shown (writes are single-digit ms); a rapid double-tap must end at `taken`, not oscillate.
4. **Tap a week-strip cell** → select that day. Tap today's cell or `backToToday` → clear the selection back to "follow today".
5. **Swipe the week strip** → previous/next week within the DECIDED-4 bounds; the strip never pages past the current week, and the resolved day follows the same weekday when paging (standard week-pager behavior).
6. **Day switching must not blank the list (PF-7):** while the new day's `dayDosesProvider` resolves, the previously rendered list stays on screen (`valueOrNull` held in screen state); the header/ring update immediately.
7. **Midnight rollover:** when `todayProvider` flips, a day-following screen re-resolves to the new day, yesterday's rows become browsable-as-missed, and the Stack tab's statuses refresh from the same provider (IN-06 closed).
8. All tap targets ≥44px: dose rows are ≥50px by construction; week-strip cells get a padded hit area so a 4px dot never defines the target.
9. The ring never animates in v1 (mockup has none); `shouldRepaint` compares only the fraction.
10. Pressed states: dose row border → `accentBorder`; week-strip cell → default ink ripple within its rounded shape. No Material elevation anywhere on this screen.

## UI Considerations

Probe run 2026-08-15 over elements E1 (day dose list — `list-collection`), E2 (dose row — `interactive-control`), E3 (week strip — `nav`), E4 (progress ring — `media`), E5 (day header — `static-content`), E6 (dose action sheet — `interactive-control`). 31 applicable category probes raised; all resolved — 19 explicit truths, 3 backstops, 0 unresolved.

**Resolved — explicit truths (planner lifts each into `must_haves.truths`):**

1. E1 empty: a day with zero doses renders `emptyDayTitle` + the correct body variant (`emptyDayBody` when the stack has entries, `emptyDayBodyNoStack` when it has none), no block headers, and NO ring (DECIDED-7); the `calendarDisclaimer` still renders.
2. E1 loading: `dayDosesProvider` `AsyncLoading` renders the header + week strip with an empty list area and NO spinner (local-DB stream resolves within a frame; a spinner would flash).
3. E1 loading (day switch): switching days holds the previously rendered list until the new day resolves — the list never blanks between days (PF-7).
4. E1 error: `AsyncValue.error` renders `dayLoadError` + `retry` (provider invalidate); no stack trace or raw exception text is ever user-visible.
5. E1 populated: only non-empty blocks render, in fixed block order, 18px apart, rows 7px apart, scroll bottom padding ≥84px so the last row clears the nav bar.
6. E1 partial: a paused regimen's pending doses are absent because `watchDay` filters them at the query level — the view renders no placeholder, no greyed row, and no "hidden" affordance for them; that same regimen's already-taken/skipped rows still render normally (PF-9).
7. E1 zero-one-many: `doseCycleChip` renders only when the regimen has >1 dose on that day, with `n`/`m` derived by grouping the day's list by `regimen.id` (never `regimen.slots.length`, PF-6); block `{done} з {total}` uses bare numerals; `ringSemantics` uses the four-form uk ICU plural, exercised at 1/2/5/11/21.
8. E1 long-text: dose names wrap inside the row (no fixed width, no ellipsis); the amount and all chips live in a `Wrap` so they break to a new line rather than clipping; the block-header divider is the flexible element so a long label or tag never overflows the header row.
9. E2 states: every dose row renders exactly one of the five states in the S4 row table (pending / overdue / taken / skipped / missed) — overdue only on today, missed only strictly before today, and never both.
10. E2 in-flight: gestures are ignored while that row's `setStatus` write is in flight; a rapid double-tap ends deterministically at `taken` (PF-4); no per-row spinner is introduced.
11. E2 error: a failed status write leaves the row at its previously rendered status (the stream is the source of truth) and surfaces `markFailed` once; no partial or "optimistic-then-reverted" visual is shown.
12. E2 long-text: the row's tap target and layout are unaffected by name length — the circle and the chip `Wrap` keep their positions while the name column flexes.
13. E3 populated: the strip always renders exactly 7 cells for the resolved week, Monday-first in both locales, dow/day-number from `intl` (never ARB).
14. E3 loading/error: the strip renders synchronously from `todayProvider` + `selectedDayProvider` and never blocks on data — a day whose summary is still loading or has errored shows the neutral `field` dot, never a spinner or an error cell.
15. E3 overflow: cells are `flex: 1` with centered text and no fixed widths; paging is bounded (52 weeks back, current week forward), so the pager has a finite `itemCount`.
16. E4: the ring is omitted entirely at `total == 0`; otherwise it always renders (0-100%), counts `taken` against all of the day's doses (skipped counts as not-taken), carries `ringSemantics`, and does not animate.
17. E5: the header always renders (title + subtitle are clock/intl-derived and can never be empty); `backToToday` appears only when the resolved day ≠ today and disappears the moment the selection is cleared.
18. E6: the action sheet renders only actions valid for the row's current status (per the DECIDED-2 transition table) — never a disabled or no-op row; dismissing it leaves the status unchanged.
19. Neutrality invariant: no `warn` or `risk` color renders on any day other than today, and no view code path writes a status — "missed" is derived in a pure helper and the raw `IntakeLog` row stays `pending` (asserted by a raw-row test).

## Layout & i18n Rules

- `EdgeInsetsDirectional` only; no fixed-width containers around any `Text` (locked; uk runs 15-25% longer than en).
- Every user-visible string from ARB keys, both files in the same commit; every count key carries all four uk CLDR plural forms (PF-8) and is exercised at 1/2/5/11/21.
- Weekday, month, and day-number strings come from `intl` `DateFormat` (`EEEE`, `d MMMM`, `E`, `d`) with the active locale — never ARB, never hand-built tables. Uppercasing of the dow label uses the locale-aware `toUpperCase()` on the intl output.
- Times render 24-hour everywhere (block header times, action-sheet subtitle) via the Phase-2 formatting helper.
- Week is Monday-first in both locales (DECIDED-4) — a deliberate divergence from `MaterialLocalizations.firstDayOfWeekIndex`, recorded here so it is not "fixed" later by accident.
- Chips size to content and live in a `Wrap`; the block-header divider is the flex element.
- Scroll body pads bottom ≥84px to clear the nav bar; the header and week strip sit outside the scroll view.
- The ring's `CustomPaint` is wrapped in `Semantics(label: ringSemantics)` — a bare canvas is invisible to screen readers.
