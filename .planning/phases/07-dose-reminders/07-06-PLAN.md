<objective>
Close the phase: turn every claim the contract makes about absence into an assertion, prove the privacy property behaviourally rather than structurally, and write down exactly what still has to be seen on a device.

Most of this phase's user-visible surface is drawn by the operating system, which means most of its guarantees are about what the app does **not** do — no supplement name on a lock screen, no interface added, no privileged permission, no blanket clear, no chrome the contract decided against. Absences have no runtime surface to test against, so they are gated as source facts. The two that can be tested behaviourally are, because a structural argument is only as good as the code that has not been written yet.

What remains after that is genuinely device-only: delivery, its timing under battery optimisation, how the text renders on a lock screen, and the two permission dialogs. Those are written into the phase's UAT list rather than dressed up as automated steps.

Purpose: all five requirements, closed and gated.
Output: two gate files, one device test, and the device-check list.
</objective>

## Device-only checks routed to the UAT list

These are stated here so no task pretends to automate them. Each becomes a numbered entry in
`07-UAT.md` in task 3.

1. A reminder is actually **delivered** at a scheduled dose time on an active day, on Android and on iOS. Nothing inside the app can observe delivery.
2. Delivery **latency** under the inexact schedule mode while the device is dozing. The accepted figure is derived rather than measured, and only a device can measure it.
3. The **lock-screen rendering**: the constant title over the time-and-count body, legible at the largest system text size, with no supplement name.
4. The **channel row** in Android's own settings: present under its localized name and description, renamed in place after the app's language is changed, with no second channel appearing.
5. The **iOS permission dialog** appearing after the first regimen save, over the screen the editor popped back to, with nothing of the app's own before or after it — and not appearing again on a second save.
6. **Denial** leaving the app fully usable with no visible trace anywhere except the Settings row.
7. Tapping a delivered reminder **cold**, after a force-quit, landing on Сьогодні with no Стек frame visible.
8. Reboot **re-arming**: reminders scheduled before a restart still arrive after it.
9. Behaviour at the platform's own pending-request ceiling. Unreachable by design given the budget, and listed so it is a known unknown rather than an assumption.

**No interface added.** Assert that no file under the notifications directory names any colour, spacing, radius or type token, and that none of them imports the theme directory. Assert that no file anywhere under the features tree has a path naming notifications — the one place feature code touches this phase is a private widget inside the existing Settings screen, and that screen's own glob gate independently asserts the feature still holds exactly two Dart files. Also record, as a note in the group's doc comment rather than as an assertion, the advisory check an executor should run by hand: a name-only diff of the whole phase's commits showing no file added or modified under the theme or shared-widget directories. It is advisory because the commit range is not derivable from inside a test, and the three assertions above are the load-bearing half.

**No ARB key of this phase is rendered by a widget.** Assert that the four notification keys resolve nowhere under the features tree and only under the notifications directory. This is the unusual invariant the contract creates: all four are rendered by the operating system, and a widget naming one would mean a screen had started restating a notification. Nothing else in the repository detects an ARB key rendered in the wrong place, and nothing else needs to.

**Lock-screen visibility on every notification.** Count the Android detail objects constructed anywhere in the app and assert the private visibility appears exactly as many times. Not "at least once" — the channel type carries no visibility parameter at all, so it must be set per notification, and a second detail object added later without it would produce public lock-screen content while the first one's presence kept a weaker gate green.

**None of the decided-against chrome.** Assert the accent colour, badge number, group key, thread identifier and interruption level appear nowhere. Each is a decision with a stated reason in the contract, and the point of writing them down was to stop someone adding one defensively; a gate is what makes that stick. Give each its own reason line: the accent budget is an in-app contract and a notification is not an app surface; the app has no unread concept so a badge is a persistent nag; both platforms already group same-app notifications; and the two elevated interruption levels need an entitlement or an approval this app has no business requesting.

**The three iOS permission-request flags are literal false.** Duplicate the file-level gate at phase level, and say why the duplication is deliberate: these three sit in the same constructor as five presentation flags that legitimately stay true and mean the opposite thing, and any one of them left at its own true default fires the one-and-only iOS prompt at launch, which breaks the "asked at first regimen save" requirement silently and unrecoverably on that device forever.

**No privileged alarm request, no blanket clear, no re-derived locale resolution.** Three needles in one forbidden map. The two alarm request methods sit on the same platform class as the methods this app does call and both are store-policy landmines for it. The privacy proof first. Build a stack whose supplement names are distinctive strings unlikely to occur by accident, seed them through mocked repositories, and drive one application of the sync against a seam that records every call. Then, for each name, assert it appears in no captured title, no captured body and no captured payload. Assert per name and per field rather than sweeping a concatenation, so a failure says which name reached which field.

The property is a security control, not a copy preference: these strings sit on a lock screen, this is health-adjacent data, and the iOS side exposes no redaction placeholder through this plugin, so the text itself is the only privacy control available there.

Then the budget proof, end to end.
