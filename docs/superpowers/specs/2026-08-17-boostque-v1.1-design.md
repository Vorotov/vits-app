# Boostque v1.1 — Design Spec

**Status:** approved in chat 2026-08-17 · **Supersedes:** nothing in v1; extends `2026-08-14-boostque-v1-design.md`
**Research input:** `docs/research/2026-08-16-notifications-research.md` (commit 66bb68f)

v1 shipped a complete plan → see → mark loop, verified on both platforms. v1.1 is five
changes requested after the first hands-on session with the real app: a slimmer and
restructured navigation, dose reminders, removal of the editorial substance limit, and a
consistent add-supplement affordance.

---

## 1. Navigation restructure

### 1.1 The bar itself

v1.1 replaces `NavigationBar` with a **hand-built bar** (`BqNavBar`), consistent with how
every other bespoke surface in this app is built.

> **Correction (2026-08-17, from Phase-6 research):** an earlier draft of this spec said
> `NavigationBar`'s 80dp height is not themeable. That is **wrong** — `navigation_bar.dart`
> resolves `height ?? navigationBarTheme.height ?? defaults.height!`, so the height *can* be
> themed. Do not transcribe the false claim into a doc comment. The real reasons to
> hand-build are better ones: the resolved height lands in a hard `SizedBox` that does not
> grow with the text scaler (the CR-01 clipping class this project has already been bitten
> by twice), and no `ThemeData` field accepts a `double Function(TextScaler)`, which is
> exactly the shape this bar needs.

| Property | v1 (`NavigationBar`) | v1.1 (`BqNavBar`) |
|---|---|---|
| Height | 80dp + safe-area | **56dp** + safe-area |
| Content | 24dp icon over a 12sp label, generous padding | 22dp icon over a 10sp label, tight |
| Selected state | pill-shaped indicator behind the icon | icon + label switch to `BqColors.accent`, weight 400 → 600 |
| Background | `surfaceAlt`, hairline top border | unchanged — the visual language stays |

The bar keeps labels. Icon-only is more compact but is a genuine accessibility and
localization regression (Ukrainian labels are the only thing distinguishing Календар from
Сьогодні at a glance), and this app has an explicit no-fixed-width-text rule.

**Text scaling:** the bar's height must grow with `MediaQuery.textScalerOf` exactly as
`WeekStrip.stripHeightFor` does — the CR-01/WR-04 lesson from v1. A fixed 56dp that clips
at 2.0 scale is not acceptable.

### 1.2 Tabs

Three destinations, replacing the current three:

| # | v1 | v1.1 | Contains |
|---|---|---|---|
| 1 | Стек | **Стек** | unchanged: the supplement list |
| 2 | Календар | **Сьогодні** | today's doses **plus the week strip and past-day browsing** (moved out of what is now the Calendar tab) |
| 3 | Налаштування | **Календар** | the planner: `Цикли \| Рік` segmented control |

**Settings leaves the bar** and becomes a gear icon in the top-right of each of the three
screens, pushing a full-screen route. The screen itself is unchanged from v1.

**Consequences to handle, not discover:**

- The v1 "planner is an in-tab page swap inside the Calendar tab" mechanism (v1's
  DECIDED-1) **is deleted**. `calendarPageProvider`, the `plannerTitle` header action and
  the `PopScope` back-interception all go; the planner is simply a tab. The `‹ Сьогодні`
  back control goes with them.
- `AppShell`'s `IndexedStack` keeps its three children, so the `TickerMode` gating added
  for v1's WR-05 stays valid — but the minute ticker now belongs to the **Сьогодні** tab.
- Deep state that survived a page swap (selected week / selected month) must survive a tab
  switch identically. v1's `resolvedWeekIndexProvider` / `resolvedMonthIndexProvider`
  identity-based selection already does this; verify, do not rebuild.

## 2. Dose notifications

### 2.1 What the user gets

One notification **per time-of-day, not per supplement**. If three supplements are due at
08:00, that is one notification reading "3 прийоми" — not three buzzes. Tapping it opens
the Сьогодні tab.

This grouping is a deliberate refinement of the original "one per dose slot" request and
wins on three axes at once: it roughly triples the iOS scheduling horizon, cuts
notification volume from ~12/day to ~4/day for a typical stack, and keeps supplement names
off the lock screen — which matters because this is health-adjacent data and iOS exposes no
`hiddenPreviewsBodyPlaceholder` through this plugin, making body content the only privacy
control available.

Notifications fire **only on days the regimen is active** — the same `isActiveOn` predicate
that drives every other surface. Paused regimens and soft-deleted supplements produce none.

### 2.2 Why the architecture is shaped the way it is

Two hard platform constraints, both verified during research:

- **iOS allows 64 pending notification requests per app**, system-wide, no exception. A
  *repeating* request counts as **one** regardless of how many times it fires.
- **Android will not permit exact alarms for this app.** Play policy limits
  `USE_EXACT_ALARM` to alarm/timer and calendar apps; `SCHEDULE_EXACT_ALARM` is
  default-denied on Android 14+, user-revocable, and the plugin *throws* rather than
  degrading — and on the boot path it silently drops the notification. v1.1 therefore uses
  `AndroidScheduleMode.inexactAllowWhileIdle`, which needs **no permission at all** and is
  what Android's own documentation recommends for reminder apps. Accepted cost: up to
  ~10-15 minutes of jitter while the device is dozing.

A third option — schedule a daily repeat and suppress it in-app on off-days — is
**impossible**, not merely worse: neither platform offers a delivery-time hook for local
notifications. Off-day filtering must happen when scheduling.

### 2.3 The two tiers

| Tier | Applies to | Mechanism | iOS cost | Failure mode |
|---|---|---|---|---|
| **A — repeating** | times where every contributing regimen runs daily (`cyclic && offDays == 0`) | one repeating request per time-of-day (`DateTimeComponents.time`) | 1 each | none — never lapses |
| **B — horizon** | times touched by a cycle with breaks, or a course | individually scheduled instances over a rolling horizon | 1 each | **goes silent after the horizon if the app is never opened** |

Budget: **60 pending requests** (leaving headroom under 64), horizon **30 days**, whichever
binds first. The horizon is topped up on every app resume — the same `AppLifecycleListener`
that already drives midnight rollover.

The honest limitation, to be stated in the UI when notification settings arrive: tier-B
reminders depend on the app being opened occasionally. For a typical stack that is roughly
a week of silence before they lapse.

### 2.4 Where it lives

- `lib/core/notifications/notification_plan.dart` — **pure**, no plugin import, no clock
  read: given regimens, a `today`, and a horizon, returns the exact set of notifications
  that should exist (tier, time, date, count, localized text keys). This is the whole
  correctness surface and it is unit-testable to the same standard as `cycle_math.dart`.
- `lib/core/notifications/notification_service.dart` — the only file importing the plugin.
  Diffs the desired plan against what is currently scheduled and applies the difference.
- Rescheduling is triggered by the same events that change dose reality: regimen created,
  edited, paused/resumed, supplement deleted, app resumed, midnight rollover.

**The timezone boundary is one line and must be got right:** local wall-clock times are
built field-wise — `tz.TZDateTime(tz.local, day.year, day.month, day.day, h, m)` — and
**never** by calling `.toLocal()` on a UTC date-only value, which would shift the whole day
for any timezone west of UTC. This is the exact inverse of the existing `dateOnly()` rule
and deserves the same doc-comment treatment.

A 03:00 dose across a DST transition is the pathological case and gets a pinned test: the
`timezone` package normalizes in pure Dart before the plugin is called, so both the spring
gap and the autumn overlap are assertable without a device.

### 2.5 Permissions and degradation

Asked the **first time a regimen is saved** — the first moment the request is meaningful —
never at launch. If denied, the app is fully functional and silently schedules nothing; no
nagging, no blocking dialog. Re-asking is a job for the deferred settings screen.

New packages (three, all necessary): `flutter_local_notifications`, `timezone`,
`flutter_timezone`. `POST_NOTIFICATIONS` and `VIBRATE` arrive via the plugin's own manifest
and must **not** be declared in ours. The app's release manifest gains no permission that
would compromise the v1 "offline, no permissions" property — verified by the existing
platform-config gate, which must be extended to cover the new manifest state.

### 2.6 Settings — explicitly deferred

No notification settings screen in v1.1, by decision. Defaults ship as described. The
deferred surface will cover: on/off, per-slot vs daily-summary, quiet hours, and a re-ask
path when permission was denied.

## 3. Remove the 5-substance editorial limit

The weekly concurrent-load chart **stays** — how many supplements overlap in a given week is
genuinely useful. What goes is every judgement layered on top:

| Removed | Kept |
|---|---|
| the dashed comfort-3 reference line | the bars themselves, and week selection |
| the `risk`-coloured over-limit bar segment above 5 | neutral `loadBar` colouring at every height |
| the `ПОНАД МЕЖУ` / at-limit / comfort verdict chips | the week-detail card, minus its verdict |
| the `межа 5 · комфорт 3` axis caption and limit badge | a plain count: "N речовин цього тижня" |
| red month counts in the Рік matrix | the matrix, counts in neutral colour |
| `weekNoteOverLimit` and the slot-pip "free slots" framing | — |
| `editorialLimit` / `comfortLoad` constants and their plural keys | — |

### 3.1 What the bars scale against (decided 2026-08-17)

Removing the limit removes the chart's y-axis: v1 sized bars as
`min(load, editorialLimit) / editorialLimit * 38`, so the limit *was* the scale.

**Decision: a full bar means "every supplement in your stack overlaps this week."** The
ceiling is the number of supplements that currently carry a schedule — it self-scales as
the stack grows, introduces no magic number, and reads as "how much of my stack is running
at once". Rejected: scaling to the busiest visible week (the ceiling would move as the
window scrolls, so the same load draws at different heights), and a fixed ceiling of 10
(an arbitrary threshold, which is the thing being removed).

Edge cases the plan must handle: a stack of 1 (a single overlapping supplement is a full
bar — correct, not a bug), and a ceiling of 0 (no scheduled supplements at all — the
planner already renders its empty state and no chart).

The educational disclaimer **stays** on both planner segments — it is the "this is a
tracking aid, not medical advice" framing, which is more important once the app no longer
offers any opinion at all.

The v1 forbidden-vocabulary gate stays and gets **stricter**: with the limit gone, words
like `межа`, `перевищ`, `норма` should now be absent from planner copy entirely.

## 4. Add-supplement affordance

A floating **+** button, bottom-right, above the nav bar, on **Стек, Сьогодні and
Календар**. Not on Settings.

- Accent fill, white glyph, the app's existing elevation language; positioned with
  `EdgeInsetsDirectional` and clearing the nav bar at every text scale.
- It opens the existing add-supplement sheet, unchanged.
- **The full-width "Додати добавку" button is removed from the Stack screen** — two
  affordances for one action is worse than either alone. The Stack empty state's body copy
  is repointed at the + button.
- Semantics: a labelled button (`addSupplement`), not an unlabelled glyph.

## 6. Testing

The v1 suite (719 tests) asserts the current tab structure in many places; churn is
expected and is part of the work, not a surprise.

- **Notification plan** — pure unit tests to `cycle_math` standard: tier assignment,
  grouping by time, off-day exclusion, pause/delete, horizon truncation, the 60-request
  budget, DST spring-gap and autumn-overlap at 03:00, and the field-wise timezone
  construction (a `.toLocal()` regression must fail a test).
- **Navigation** — the three tabs, settings pushing and popping, week-strip browsing inside
  Сьогодні, planner segment state surviving tab switches, and the nav bar not clipping at
  text scale 1.0/1.6/2.0 in both locales.
- **Planner** — the removal is asserted, not assumed: no verdict chip, no reference line, no
  `risk` colour on the load chart or year counts, and the widened vocabulary gate.
- **FAB** — present on exactly three screens, absent on Settings, opens the sheet, reachable
  by semantics activation.
- **Device** — both existing on-device tests must still pass on iOS and Android; a
  notification test is device-bound and will be scoped when the phase is planned.
